## Recommended execution order

1. **002** and **004** first — smallest, single-file, zero dependencies, immediate wins (fix a performance anti-pattern, add press feedback everywhere via the shared button classes).
2. **001** and **005** next — both touch dialog/drawer entrance motion; can be done in either order or in parallel since they touch different files.
3. **003** — once 001/004 exist, sweep in the shared tokens and update their inline easing to match (optional but recommended for long-term consistency). Safe to do first instead if preferred — each plan works standalone either way.
4. **006** last — blankets all motion added by the above with `prefers-reduced-motion` support, so it should land after the motion it's meant to gate exists (though the rule itself is harmless if applied earlier).

## Notes

- Plans 1-6, 8, and 9 add zero new npm dependencies — everything was achieved with Tailwind utilities + minimal React state. Plan 7 added `@base-ui-components/react` (1.0.0-rc.0) and `sonner` (2.0.7), plus two new shared components: `src/components/ConfirmDialog.jsx` and `src/components/PromptDialog.jsx`.
- Plan 9 came from the `ui-ux-pro-max` skill (installed to `.claude/skills/`) flagging "single error banner at top of form" against its UX guideline database, rather than from the original `improve-animations` audit. It depends on Plan 7 having landed (routes generic failures through `toast.error()`).
- A shared `Modal` component to de-duplicate `AboutModal`/`VisitEntryModal` markup (they still use their own local `mounted`-state fade pattern rather than the base-ui dialogs from Plan 7) was flagged as a missed opportunity during the original audit and remains unplanned.
- To execute a plan: hand its file to any coding agent (or run it yourself) — each plan is self-contained with exact file:line references, target values, and a verification checklist.
